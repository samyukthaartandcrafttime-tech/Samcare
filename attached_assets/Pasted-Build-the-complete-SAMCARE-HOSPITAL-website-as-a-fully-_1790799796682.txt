# RAPID ASSIST: INJURY IMAGE

Allow the patient to:

1. Upload an injury image.
2. Preview the image.
3. Start Rapid Assist analysis.
4. Display a realistic scanning animation.
5. Display progressive analysis stages.
6. Show visible observations.
7. Identify an appropriate care category.
8. Recommend an appropriate doctor.
9. Create a clinical summary.
10. Save the case to LocalStorage.
11. Send the case to the appropriate doctor's dashboard.
12. Create a nurse/staff alert.
13. Add the event to the patient's Care Journey.

The visual process should feel like actual analysis is happening.

Show stages such as:

**Image Received**

**Scanning**

**Visible Features Identified**

**Care Category Determined**

**Doctor Matched**

**Clinical Summary Prepared**

**Secure Handoff Complete**

Do not pretend that the browser is performing medically validated diagnosis.

Clearly distinguish:

**WHAT IS VISIBLE**

from

**WHAT REQUIRES CLINICAL CONFIRMATION**

Example:

Affected Area: Hand

Visible Observations:

* Localized swelling
* Visible discoloration
* Superficial wound visible

Preliminary Concern:
**Musculoskeletal injury may require clinical assessment**

Confidence:
**Moderate**

Recommended Next Step:
**Clinical evaluation recommended**

Never claim that an image definitively proves a fracture, infection, disease, or other diagnosis.

# IMPORTANT: SHARED DATA

This is NOT supposed to be several disconnected pages.

Use LocalStorage as the shared application state.

For example:

When Alex submits a Rapid Assist case:

1. The case is saved.
2. The appropriate doctor receives it.
3. The nurse/staff portal receives an alert.
4. Alex's notification updates.
5. Alex's Care Journey updates.
6. The doctor's Rapid Assist queue updates.

When Alex books an appointment:

1. Patient dashboard updates.
2. Doctor dashboard updates.
3. Nurse/staff queue can update.

When the doctor completes a consultation:

1. Consultation Memory is created.
2. Patient records update.
3. Prescription can be created.
4. Follow-up can be scheduled.
5. Care Journey updates.

Everything should use the same LocalStorage data.
